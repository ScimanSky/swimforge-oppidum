6. Anti-Cheat e Validazione

⚠️ CRITICO: L'anti-cheat è fondamentale in un modello swim-to-earn. Senza validazione, gli utenti potrebbero falsificare attività per guadagnare token.
LivelloControlloImplementazione
L1 — BaseSource verificationSolo dati da Garmin/Strava API, no input manuale
L2 — PlausibilitàPace range checkPool: 1:00-3:30/100m, OW: 1:20-4:00/100m
L3 — HRHeart rate correlationHR deve correlare con pace dichiarata
L4 — FrequenzaMax 3 earn/giornoOltre 3 sync → solo log, no $SWIM
L5 — MLAnomaly detection (futuro)Pattern GPS, durata, anomalie statistiche

Regole di validazione

IF source ≠ (Garmin | Strava)        → 0 $SWIM (L1)

IF pace < 1:00/100m OR > 3:30/100m  → 0 $SWIM (L2)


IF HR_available AND HR < 80bpm       → flag per review (L3)


IF daily_earn_count ≥ 3             → log only, no earn (L4)
